# Examples

Worked examples by capability. Each example is short, self-contained, and uses bundled grammars so it runs immediately after `pip install rawast` (or `pip install -e .` from the repo).

Runnable scripts live in [`../examples/`](../examples/). Inline examples in this doc are paste-into-`python` ready.

## Parse → modify → save

The five-line bidirectional-walk demo. Load a grammar, parse a file into a Python value, edit it like a normal dict, save it back through the same grammar.

```python
import rawast

g = rawast.Grammar("json")

value = g.parse_string('{"name": "alice", "items": [1, 2, 3]}')
value["name"] = "bob"
value["items"].append(4)

text = g.save(value, pretty=True).decode("utf-8")
print(text)
# {
#   "name": "bob",
#   "items": [1, 2, 3, 4]
# }
```

Swap `"json"` for `"gdsii"`, `"lefdef"`, or `"tcl"` to do the same dance against a different format. Runnable: [`examples/json_edit.py`](../examples/json_edit.py).

## Cross-format conversion

Parse with one grammar, save through another. Useful for GDSII → JSON dumps (e.g. piping a layout into `jq`), or `.rawast` → `.json` to inspect a grammar's data form.

```python
import rawast

gdsii  = rawast.Grammar("gdsii")
json_g = rawast.Grammar("json")

# GDSII binary → JSON text
ast = gdsii.parse_file("layout.gds")
print(json_g.save(ast, pretty=True).decode("utf-8"))
```

The bytes the JSON saver emits are valid JSON because the value tree is JSON-shaped by design — every grammar produces dicts / arrays / scalars, never a format-specific type.

The same trick works for grammar files themselves — `.rawast` ↔ `.json`:

```sh
# .rawast → JSON form
rawast convert --read grammars/rawast.rawast \
               --write grammars/json.json \
               grammars/lefdef.rawast > lefdef.json
```

## Multi-top-rule grammar: pick `LEF` or `DEF`

`grammars/lefdef.rawast` ships with two top rules. Tell the engine which language you're handling via `start=`:

```python
import rawast

g = rawast.Grammar("lefdef")

# Parse a tech LEF
tech = g.parse_file("sky130hd.tlef", start="LEF")
print(f"LEF items: {len(tech['items'])}")

# Parse a DEF placement
plc = g.parse_file("gcd.def", start="DEF")
print(f"DEF design: {plc['design']['name']}")

# Save back — same start= parameter on save
out_bytes = g.save(plc, start="DEF")
```

Both `parse_*` and `save` accept `start=`. The grammar's named rules become candidate entry points.

## Generate Pydantic models from a grammar

`rawast pydantic` emits a Python module whose classes mirror the grammar's parse/save dict shape. The result is round-trip-faithful: validate a parsed dict, edit the typed model, dump back to a dict, save through rawast.

```sh
rawast pydantic grammars/lefdef.rawast > lefdef_models.py
```

```python
import rawast, lefdef_models as M

g = rawast.Grammar("lefdef")
parsed = g.parse_file("sky130_fd_sc_hd.lef", start="LEF")

lef = M.LEF.model_validate(parsed)              # typed model now in `lef`
lef.items[0].pins[0].direction = "OUTPUT"        # edit with autocomplete

dumped = lef.model_dump(exclude_none=True, by_alias=True)
assert dumped == parsed or dumped != parsed     # depending on what you changed

with open("edited.lef", "wb") as f:
    f.write(g.save(dumped, start="LEF"))
```

The model carries `ConfigDict(extra="forbid", populate_by_name=True)` — it rejects fields the grammar can't save, and accepts both field names (`class_`) and aliases (`class`) at construction time.

## Real file → typed Python source (`rawast pycode`)

`rawast pycode` reads a real file, validates it against the Pydantic model, then emits Python source that constructs the same model. The output is a runnable module you can edit with autocomplete + Pydantic validation, then run to regenerate the original.

```sh
# Generate the Pydantic models
rawast pydantic grammars/lefdef.rawast > models.py

# Read the file, emit Python that reconstructs it
rawast pycode grammars/lefdef.rawast sky130_fd_sc_hd.lef \
    --start LEF --models-module models > fixture.py

# Run the generated module to regenerate the file
python fixture.py > sky130_fd_sc_hd.regenerated.lef
```

The generated `fixture.py` is a self-contained module:

```python
"""Generated by `rawast pycode`.
Source file: sky130_fd_sc_hd.lef
"""
from models import *

obj = Lef(
    hdr=Hdr(version=5.8, bus_bit_chars='[]', divider='/'),
    items=[
        MacroBlock(
            type='Macro',
            name='sky130_fd_sc_hd__buf_1',
            classes=['CORE'],
            ...
        ),
        ...
    ],
)

if __name__ == "__main__":
    import sys, rawast
    g = rawast.Grammar.load('grammars/lefdef.rawast')
    sys.stdout.buffer.write(g.save(obj.model_dump(exclude_none=True, by_alias=True), start='LEF'))
```

**Use cases:**
- Test fixtures — convert a real corpus file into self-contained Python.
- Tutorials — readable typed code mirroring a real LEF/DEF/GDSII.
- Programmatic editing — start from a real file, edit in your IDE, save back.

**Limitations:**
- Output size grows linearly. Multi-MB inputs produce multi-MB Python sources. Practical for files <~5 MB.
- No loop / comprehension synthesis: 1,000 similar macros emit 1,000 separate constructor calls.

## Tcl: recursive re-parse of `if` / `proc` bodies

The Tcl grammar captures `"…"` strings with automatic `$var` / `[cmd]` substitution and captures `{…}` blocks as literals. The application drives the second pass on braced bodies when context says "this is code" — exactly how Tcl's runtime evaluates `if { … }` and `proc { … }`.

```python
import rawast

tcl = rawast.Grammar("tcl")
script = tcl.parse_file("flow.tcl")

for cmd in script.get("commands", []):
    if not cmd or cmd.get("type") != "command":
        continue
    words = cmd["words"]
    if not words:
        continue

    # First word is the command name. For `if`, the third word is a
    # brace body that's itself a Tcl script — re-parse it on demand.
    first = words[0]["value"]["segments"][0].get("value")
    if first == "if" and len(words) >= 3 and words[2]["type"] == "brace":
        body = tcl.parse_string(words[2]["value"], start="SCRIPT")
        print(f"Found if-body with {len(body['commands'])} commands")
```

Same engine, called recursively from host code. The `start="SCRIPT"` argument names the rule the inner parse enters at; pass a different rule (e.g. `start="WORD_SEGMENTS"`) to re-enter a sub-language's entry point instead.

## GDSII: parse a binary file and walk the structure

GDSII is binary, but the value tree is the same JSON shape as any text format.

```python
import rawast

g = rawast.Grammar("gdsii")
lib = g.parse_file("layout.gds")

print(f"Library: {lib['name']}")
print(f"Structures: {len(lib['structures'])}")

# Find all BOUNDARY elements on layer 10
for struct in lib["structures"]:
    for elem in struct.get("elements", []):
        if elem.get("type") == "boundary" and elem.get("layer") == 10:
            print(f"  {struct['name']}: boundary at {elem['xy']}")

# Save back — byte-equivalent round-trip
with open("layout.regenerated.gds", "wb") as f:
    f.write(g.save(lib))
```

For text-format conversions:

```python
# Dump GDSII as JSON
json_g = rawast.Grammar("json")
with open("layout.json", "w") as f:
    f.write(json_g.save(lib).decode("utf-8"))
```

## Lint a grammar before shipping

The structural linter catches design bugs (LL(1) ambiguity, nested-Choice-type-emit anti-pattern, raw-consume misuse) at grammar-load time. Run it as part of CI for any grammar you ship.

```sh
rawast lint grammars/mygrammar.rawast
# clean → exit 0, no output
# issues → paragraphs naming the rule and the problem, non-zero exit
```

```python
import rawast

g = rawast.Grammar.load("grammars/mygrammar.rawast")
issues = g.lint()
if issues:
    for s in issues:
        print(s)
    raise SystemExit(1)
```

## Per-rule parse profiling on a corpus

Aggregates per-rule entry count / fail count / cumulative time across a corpus. Sorted by `time` / `count` / `fails`; use `--top all` for the full list.

```sh
# Single file with the top-30 rules
rawast parse grammars/lefdef.rawast sky130_fd_sc_hd.lef \
    --profile --profile-top 30 > /dev/null

# Whole corpus with the slowest 50 rules
rawast profile grammars/lefdef.rawast --from-file lef_corpus.txt \
    --by time --top 50
```

Output (stderr):
```
corpus profile: 263 files, 60.92ms total parse, 4,201,318 frames, max depth 28, sorted by time
  rule                                      calls     fails             ns    pct  depth
  ----------------------------------------------------------------------------------
  LAYER_BODY_ITEM                          412184         0    18,201,512   24.1%      7
  MACRO_BODY                               120044         0    12,331,805   16.3%      9
  ...
```

The profile counters are shared between the parse engine and the linter, so what you see in profiling matches what the engine actually dispatched.

## Stream — share one input across grammars

`rawast.Stream` is the canonical parser-input type. `parse_string` / `parse_file` / `parse_bytes` are sugar over `Stream.from_string` / `Stream.from_file`. Hold a Stream when you want to control where the bytes come from, or compose pipeline stages without re-reading.

```python
import rawast

g = rawast.Grammar("json")

s = rawast.Stream.from_string('{"name": "alice", "items": [1, 2, 3]}')
ast = g.parse_stream(s)

# Same idea from a file path:
ast = g.parse_stream(rawast.Stream.from_file("config.json"))

# parse_stream accepts the `start=...` kwarg the same way the other
# overloads do (multi-top-rule grammars like lefdef):
g2 = rawast.Grammar("lefdef")
ast = g2.parse_stream(rawast.Stream.from_file("flow.def"), start="DEF")
```

## SystemVerilog preprocessor — three modes

The `Preprocessor` exposes its pipeline at three independent joints. Pick the joint that matches your use case.

```python
import rawast

pp_g = rawast.Grammar("sv_preprocessor")
pp   = rawast.Preprocessor(pp_g)

src = open("design.sv").read()

# Mode 1 — parse the directives into an AST without expanding anything.
# Useful for inspecting `define / `include / `ifdef structure (LSP-ish
# tooling, dependency tracking, lint of macro hygiene before expansion).
# No state mutation: pp.macros stays empty.
ast = pp.parse(src)
for item in ast:
    if item["type"] == "define":
        print("defines macro:", item["name"])

# Mode 2 — expand the AST into a Stream of preprocessed bytes. Walker
# state (macros, included_files, warnings, source spans) accumulates on
# the Preprocessor instance.
stream = pp.preprocess(ast, src)

# Mode 3 — feed the Stream straight into the host SV grammar.
sv = rawast.Grammar("systemverilog")
top = sv.parse_stream(stream)

# One-shot shortcut when you don't need the intermediate stages:
expanded_text = pp.process(src)            # -> str of expanded bytes
top = sv.parse_string(expanded_text)
```

Modes can be combined freely — Mode 1 alone is enough if you only want directive structure; Mode 2 → Mode 3 is the typical "preprocess then parse" pipeline. The same `Preprocessor` instance accumulates macro state across calls, so a multi-file corpus reuses one `pp`.
